# 区間ラベリング（`--label-sections`）の実行手順

正解ラベル `labels.tsv` を人間が付けるための CLI。
[section-analysis-redesign.md](section-analysis-redesign.md) の Stage 3 はこれ待ちで止まる。

Docker（`./dev.sh`）は音声デバイスを持たないので、**ラベリングだけホストで実行する**。

## アウトロ境界の定義

**単一の1文では書けない。** 曲の構成によって拠り所が変わり、片方は確実、
もう片方は確実でない。**あいまいな側を無理に一意へ潰さないこと**が定義の一部である
（2026-08-04 の再聴取で決着。→ 下記「対照2曲で何が起きたか」）。

**歌がある曲 — 一意に決まる。**

> 歌が終わる → 曲のフレーズ、または何か特徴的なフレーズが継続する（**ほとんどの場合
> 16小節**）→ そのあとアウトロへ移行する。アウトロの開始はこの移行点の小節頭。

歌の終わりは耳で明確に取れる出来事なので、これがアンカーになる。継続部が16小節から
外れることはあるが、探すのは「歌の終わり」と「そこから継続したフレーズが終わる点」の
2つだけでよい。

**歌がない曲 — 一意に決めない。**

音の減り方はイントロの増え方を逆順にたどるので、**イントロと対称形になることが多い**。
ただしこれは傾向であって確実ではない。**歌以外の基準は意図的にあいまいなままにする。**
確実でない基準を1文へ固めると、教師データ側にぶれが入り、推定器の誤りと区別が
付かなくなる。

### 「音が減る」は曲中に何度も起きる

**Funkot には曲の途中で減速する曲が多い。** そして減速の前には音が減る。つまり
**「編成が減るだけになる点」は1曲に複数ある**ので、最初の1つを取ると必ず早すぎる方へ
外れる。これが 8-04 に定義文を捨てた直接の原因である。

暫定の切り分け:

> 音が減る点が複数あるとき、アウトロはそのうち**あとに加速も再構築も来ないもの**
> （＝最後の1つ）。**減速区間そのものはアウトロではない。**

**歌がある曲ではこの問題が自動的に消える。** 減速は歌より前に置かれるのが普通なので、
「歌の終わり」をアンカーにすると減速を跨がずに済む。歌が無い曲では跨げない。
**歌なし曲の基準が本質的にあいまいなのはこのため**であって、聴き手の不注意ではない。

減速のある曲には **`DECEL:yes`** を書く（→ 下「メモの書式」）。何曲がこの構成なのかが
分からないと、暫定の切り分けを規則へ格上げしてよいかを判断できない。

したがってこの種の曲では:

- `outro_best` には最も素直な候補（多くはイントロと対称な値）を入れる
- **`a` で対抗候補を必ず `outro_ok` に入れる。** ここを空にすると、決められない
  はずのものを決めたと主張することになる
- 評価で見るのは `tolerant` と DJ重大度コスト。**`OUTRO exact` はこの種の曲では
  意味を持たない**（→ [section-analysis-redesign.md](section-analysis-redesign.md)
  「採用基準」）

### 対照2曲で何が起きたか

「新しい要素が入らなくなり編成が減るだけになる最初の小節頭」という1文を検証するため、
すでに正解している2曲を聴き直した:

| 曲 | 元ラベル | 旧定義で再聴取 | 新定義で再聴取 | |
|---|---|---|---|---|
| Alvian - Yao Bu Neng Ting | 64 | 64 | — | 一致 |
| KazuyaP - Monitoring Db | 32 | 64 | **48** | 3回とも別の値 |

対照が割れた時点で、**ぶれていたのは推定器ではなく定義文のほう**だと分かる。
Monitoring Db の構成は特殊で、**「音が減る」が2回ある**:

```
イントロ → 音が減る → 減速 → 歌 → 歌が終わる → 加速
        → 曲のメロディーのシンセフレーズ → アウトロ
```

1回目の「音が減る」は減速の前置きであってアウトロではない。「最初の小節頭」という
文言がここを拾いにいく。

**新定義で3回目を聴いた結果は 48 で、事前に書いた「答えは 32」は外れた**ので
その対応付けは消した。ラベルは末尾からの小節数なので **64（歌が終わる点）−
16（継続フレーズ）= 48** であり、48 は**歌あり分岐の式そのまま**の値である。
32 が何であるかは未確定のまま置く。

この回は**メモが1曲も書かれていない**ので、上の読みは値の算術が合うというだけで
裏は取れていない。**`VOX:` が無いと歌あり分岐を適用したのかも確かめられない。**

同じ回で `Totsumal` と `Eternal Light` も 48 → **64** へ動いた。3曲の移動は
すべてちょうど ±16小節＝継続フレーズ1つ分で、**残っているあいまいさは
「継続フレーズをアウトロに含めるか」に集約している可能性がある**。未確認。

## 前提（一度だけ）

```sh
sudo apt install -y libclang-dev          # signalsmith-stretch の bindgen が要求
sudo apt install -y libasound2-plugins    # WSL2 に ALSA カードが無く cpal が落ちるため
# ~/.asoundrc に pcm.!default / ctl.!default { type pulse } を置く
# WSLg の PulseAudio は PULSE_SERVER=unix:/mnt/wslg/PulseServer で既に動いている
```

## ビルドと実行

```sh
# target/ は Docker 名前付きボリュームの root 所有マウント点なので別ディレクトリを使う
CARGO_TARGET_DIR=target-host \
PKG_CONFIG_PATH=/usr/lib/x86_64-linux-gnu/pkgconfig:/usr/share/pkgconfig \
  cargo build -p funkot-cli --release

# キャッシュを事前に温める（CACHE_VERSION が上がると全再解析になる）
./dev.sh cargo run -p funkot-cli --release -- \
  -l testdata/file_list.txt --cache-dir funkot-cache --fill-missing-cache --jobs 0

# ラベリング
./target-host/release/funkot-autodj \
  --label-sections -l testdata/file_list.txt --labels testdata/labels.tsv \
  --cache-dir funkot-cache
```

**`./label.sh` が上のビルドとラベリングをまとめて行う。** パスを手で打たなくて済むので
常にこちらを使う（`--labels` の打ち間違いで別の場所に `labels.tsv` を作る事故が実際に
起きた）。追加の引数はそのまま渡る。`./label.sh --no-build` でビルドを飛ばせる。

**一部の曲だけを相手にするときは `./label.sh --list FILE`。** 既定の
`testdata/file_list.txt`（60曲）を差し替える。`--list` は funkot-autodj へ素通しできない
（`-l` を2回渡すと clap が `cannot be used multiple times` で弾き、位置引数との併用も
`resolve_playlist` が拒否する）ので、label.sh が受け取って自分の `-l` に使う。
**相対パスは呼び出したディレクトリ基準**で解決される（既定値だけはスクリプト位置基準）。
リスト**の中身**の相対パスはリストファイル自身のディレクトリ基準なので、
`testdata/` に置けば `file_list.txt` の行をそのまま流用できる。

`PKG_CONFIG_PATH` が要るのは PATH 先頭の Homebrew 版 pkg-config が
`/usr/lib/x86_64-linux-gnu/pkgconfig` を見ないため（ALSA 自体は入っている）。

**ホストとコンテナは別の target を持つ。** `./dev.sh cargo test` が通っても、
`--render-clips` で書いたクリップが正しくても、`target-host` のバイナリは古いまま。
クリック位置や候補の出方を変えたら、聴く前に**必ず上のビルドをやり直す**
（症状: 直したはずのずれがラベリング中だけ再現する）。

## 大量の曲を扱うとき

`-l LIST.txt` に自分のライブラリのファイルを直接並べてよい。**変換して置き直す必要はない。**

**リストの行はパスであってファイル名ではない。** 絶対パスはそのまま、相対パスは
**リストファイル自身のディレクトリ**基準（CWD 基準ではない）で解決される。
`testdata/file_list.txt` がファイル名だけなのは曲がリストと同じ場所にあるからで、
制約ではない。ライブラリの曲は `/mnt/oldpc/music/...` のような絶対パスで足せばよい。

- **ALAC(m4a) は変換不要。** symphonia が直接読む（`alac` + `isomp4` feature）。
  実測で、同じ音源の ALAC と FLAC の解析結果は完全一致した
- symphonia が読めない形式（Opus / WMA / AIFF / APE 等）は、`ffmpeg` が PATH にあれば
  自動で FLAC へ変換して読む。変換物は `FUNKOT_CONVERT_DIR`（既定
  `$XDG_CACHE_HOME/funkot-autodj/converted`）に**元ファイルの content_hash 名**で
  キャッシュされ、2回目以降は ffmpeg を起動しない
- **曲の正体は常に元ファイル。** `labels.tsv` と `funkot-cache` のキーは元ファイルの
  content_hash なので、**変換キャッシュを消しても ffmpeg を上げても、手で付けたラベルは
  そのまま有効**。ディスクが厳しくなったらキャッシュごと消してよい
- **`./dev.sh`（Docker）には ffmpeg が入っていない。** 未対応形式をコンテナ内で渡すと
  「ffmpeg が無い」と言って失敗する。ラベリングはホスト実行なので実用上は問題ない
- ライブラリが read-only マウントでも動く（変換物を元ファイルの隣に置かないため）

## 操作

`y`/Enter 採用 · `←`/`→` 候補移動 · `+` ±8/±16小節切替 · `r` 頭から再生し直し ·
`a` 曖昧（許容集合トグル）· `n` メモ · `s` スキップ · `q` 保存して終了。

**再生は `--rate`（既定 1.10）倍速で鳴る。** 本番の DJ 再生は常にこの速度で
加速されているので、ラベルもその速度で耳判断したほうが実態に合う。ピッチは
既定で保つ（`Preserve`）。`--pitch-shift` を付けるとピッチはテンポと一緒に
上がるが、キー入力ごとにクリップを作り直す待ち時間（既定のピッチ保持だと約1.2秒）
が消える。実測は 106秒クリップで **1.67s（ピッチ保持）対 0.46s（`--pitch-shift`）**。**`--render-clips` で書き出すクリップはこの対象外で、常にソースの
等速のまま**（クリップ合成そのものを検証する用途のため）。

**再生は ±8小節の窓で止まらず、そのまま先へ進む**（イントロ側・アウトロ側とも）。
窓だけでは「境界クリックが小節頭に乗っているか」しか分からず、ラベルを決める
2つの判断——**クリックが早すぎるときにどれだけずれているか**（本当に切り替わる場所まで
聴かないと分からない）と、**アウトロが段階的に音を落とすときにアンカーが
耳の言う「終わり」と一致しているか**——には窓の**後ろ**の素材が要るため。

- 窓の後ろに最大 `CONTINUE_AFTER_WINDOW_BARS`（64小節）続け、**ファイル終端で打ち切る**
- したがって**アウトロ側は必ず曲の最後まで鳴る**（実測 Sakura Photograph:
  outro 8→21小節 / 16→29 / 32→45 / 48→61 / 64→77。いずれも EOF で終わる）。
  イントロ側は曲が長いので常に 80小節（16+64、約107秒）
- **小節クリックは最後まで鳴り続ける**（定規として使うため。境界クリックだけが二連打）。
  クリック音量は**窓の部分の RMS** から決める。クリップ全体で測るとフェードや無音に
  引きずられて、窓の中のクリックまで小さくなってしまう
- 止まるのは `y`（採用）・`s`（スキップ）・`q`（終了）、または再生し切ったとき。
  `r` で頭から鳴らし直す

`s`/`q` を押したときも、その時点で入力済みのメモは保存される。このときラベル欄は
（未確定の側は）空欄のまま書かれ、空欄は「その側はまだラベル付けされていない」意味
になるので、その曲は次回も出題される。候補格子に載らない境界に遭遇したら、無理に
近い候補を選ばず `n` でメモを残してから `s` すればよい（下記「注意」参照）。

**`←`/`→` は先読みが効く。** 再生を始めた時点で両隣の候補を裏で作るので、
そのどちらかへ動くぶんには待ちが無い。飛び先・側の切り替え・その曲の初回だけは
生成待ちになる（**イントロ約1.75秒 / アウトロ約0.85秒**、大半は伸長処理）。
先読みキャッシュは1曲あたり4本・最大約180MB。

1曲ごとに保存され、既ラベルの曲はハッシュでスキップされるので中断・再開できる。
クリックが聞き取りにくい／ダッキングが邪魔なら `--click-db`（既定 12.0）と
`--click-duck-db`（既定 18.0）で調整する。

**注意**: UI の `OUTRO_CANDIDATES {8,16,32,48,64}` は**構造境界**の集合として妥当
（ラベルは構造境界を記録する。mix トリガはそこから `+16小節` で導出され、
集合は {24,32,48,80}）。ただし候補格子に載らない構造境界に遭遇したら、
無理に近い候補を選ばず **`n` でメモを残す**こと。数が溜まったら候補集合の拡張を検討する。

クリックが小節頭から外れて聞こえた場合も `n` メモを残す
（[guide-clicks.md](guide-clicks.md) の「テンポ refit の限界」に該当しうる）。

## メモの書式

`n` のメモは自由文でよいが、**あとで集計したいものはタグで書く**。自由文のままだと
60曲ぶん溜めても目視でしか読めない。

書式は `KEY:VALUE` を空白区切りで並べるだけ。自由文と混ぜてよい:

```
PH:half クリックが1拍手前で鳴る
```

`KEY` は ASCII 大文字で始まる2文字以上（`[A-Z0-9_]`）。日本語の文や小文字の語、
`http://` のような文字列が偶然タグとして読まれないための制限なので、緩めないこと。
パーサは形しか見ないので、**語彙は運用上の約束**である:

| タグ | 意味 | 値の例 |
|---|---|---|
| `VOX:` | 歌があるか（アウトロ定義のどちらの分岐を使ったか） | `yes` / `no` / `?` |
| `DECEL:` | 曲の途中に減速があるか | `yes` / `no` |
| `PH:` | ガイドクリックが小節頭で鳴っていたか | `ok` / `beat+1` / `beat-1` / `half` / `?` |
| `GRID:` | 候補集合に載らない構造境界に遭遇した | `24`（耳で聞こえた小節数） |
| `DUP:` | 同一曲の別バージョン。同じ値を両方に書く | `kekka-orai` |

**`VOX:` と `DECEL:` は毎曲書く。** アウトロ境界の定義は歌の有無で分岐し、
歌なし側のあいまいさは減速の有無から来る（→ 上「アウトロ境界の定義」）。
両方無いと「歌あり曲では一意に取れて歌なし曲では取れない」という主張そのものを
あとから検証できない。`VOX:no` の曲で `outro_ok` が空なら、それは定義違反として
見つけられる。`VOX:?` は「歌はあるが終わりが取れない」（フックの断片が最後まで
散らばる等）に使う。

**`DECEL:yes` は解析器側にも意味がある。** BPM は先頭/末尾の各110秒から推定され
（`analysis.rs`）、180BPM では 110秒 ≈ 82小節 ≈ `MAX_SCAN_BARS_OUTRO`(80) なので、
**末尾80小節の中に減速や加速があるとそれは BPM 推定窓の中に入る**
（→ [section-analysis-redesign.md](section-analysis-redesign.md)
「曲中の減速がテンポ推定窓に入る」）。減速が曲のどのあたりかも一言添えると役に立つ
（`DECEL:yes 歌の前`）。

`PH:` は**すでに聴いているものを1語書くだけ**である（小節クリックは窓の後ろでも
最後まで鳴り続ける）。位相の対処を設計するには「壊れている曲がどれだけあるか」の
正解が要るが、いまある60曲の測定はすべて正解なしなので、これが唯一の供給源になる。

`DUP:` だけはコードが読む。`eval_sections` の k-fold 分割が同じ `DUP:` 値を持つ曲を
**同じ fold へまとめる**ので、同一曲の別バージョンが訓練とテストに跨がらない
（White Label の `Kekka Orai` 2バージョンが該当する）。他のタグは集計表示だけ。

集計は `eval_sections` が「note tags」節に出す。タグを1つも持たない非空のメモも
一覧されるので、書き損じは見れば分かる。**タグが1件も無いうちはこの節は出ない。**

## 片側だけ聴き直すとき

曲が出題される条件は `intro_best` と `outro_best` の**両方が埋まっていること**
（`main.rs` の `labeled` 集合）。したがって**聴き直したい側のセルを空にすれば
その曲は再び出題される**。`labels.tsv` を消す必要はない。

ただしセッションは**必ずイントロ側から始まる**（`label_session.rs` の
`TrackSession::new` が `side: Side::Intro` で初期化する）。アウトロだけ聴き直す場合も
イントロ側で1回 `y` を押して通過することになる:

- イントロのカーソルはキャッシュの `intro_bars` から始まり、その値は
  `set_manual_bars` が書いた**手入力済みラベルそのもの**なので、`y` は同じ値を
  書き直すだけで済む。**カーソルを動かさないこと**（動かすと既存ラベルが壊れる）
- ただし `y` は**許容集合も空で上書きする**。イントロ側にも `a` を付けたいなら
  通過するこの機会に付ける
- アウトロのカーソルは `outro_structure_bars` から始まる。こちらは
  `set_manual_bars` が書かないので**解析器の予測値**であり、
  「推定値を先に聴いてから真値と比べる」用途にはそのまま都合がよい

作業前に `cp testdata/labels.tsv testdata/labels.tsv.bak-MMDD` を取ること。

### 推定値とラベルを突き合わせる聴き方

「解析器の予測が正しいのか、ラベルが正しいのか」を決めたいときの手順。
アウトロ側のカーソルが予測値から始まる性質をそのまま使う:

1. 開いた位置（＝**予測値**）を聴く。二連打のクリックの時点で**何が変わったか**を
   言葉にする（「最後の一撃」「メロが消えた」「落とし始めた」のどれか）
2. `←`/`→` で**記録済みのラベル値**へ移り、同じ問いを立てる
3. 決めた定義に照らして勝ったほうを選ぶ
4. **負けたほうも DJ として間違いでないなら、その位置で `a` を押す**（許容集合）。
   そのうえで勝ったほうへ移って `y`
5. `n` で `PH:` を書く。どちらも違うなら `GRID:<耳の小節数>` を書いて `s`

評価は `eval_sections` を **`--cache-dir` 無しで**回して取り直す。

## ラベルを捨ててやり直すとき

`labels.tsv` を消すだけでは元に戻らない。**ラベリングはキャッシュも書き換える**:
1曲終えるたびに `cache::set_manual_bars` が `intro_bars` をラベル値で上書きし
`intro_bars_manual: true` を立てる（アウトロ側は書かない。cache v10 でリードは
`+16小節` 固定になったので推測ではなくなったが、書き込みはまだ実装していない
→ section-analysis-redesign.md の Stage 4 残り）。この上書きは**元に戻せない** — `set_manual_bars` の
`None` は「変更しない」であって「クリアする」ではなく、解析器が本来出した
`intro_bars` はキャッシュのどこにも残っていない。

放置すると、UI の初期候補も `eval_sections` の入力も旧ラベル由来の値に
引きずられる。やり直すときは該当エントリを**捨てて作り直す**:

```sh
rm -f testdata/labels.tsv
rm -f $(grep -lE '"(intro|outro)_bars_manual" *: *true' funkot-cache/*.json)
./dev.sh cargo run -p funkot-cli --release -- \
  -l testdata/file_list.txt --cache-dir funkot-cache --fill-missing-cache --jobs 0
grep -lE '"(intro|outro)_bars_manual" *: *true' funkot-cache/*.json | wc -l   # 0 を確認
```

解析は決定的なので再解析で元の推定値に戻る。**中断したセッションの残骸**が混じる点にも
注意（`labels.tsv` に行が無くてもキャッシュにだけ manual フラグが立っていることがある。
実際 2026-07-31 のやり直しでは 5行に対して 6件が該当した）。

### 汚染されたキャッシュで評価しないこと

この上書きのせいで、**`eval_sections` に `--cache-dir` を渡すと INTRO の予測値が
ラベル値そのものになり、精度が偽装される。** 実測（14曲）で
INTRO exact が **0.929 → 1.000** に化ける。

`eval_sections` は manual フラグの立ったエントリを数えて警告を出すので、
気付かず通ることはもう無い。**評価は `--cache-dir` 無しで回す。**

ガイドクリックの位置を変える修正を入れたあとにやり直す場合は、**ホストの
`target-host/release/funkot-autodj` を再ビルドしてから**始めること。古いバイナリは
修正前のアンカーでクリップを作る。

## WSLg の PulseAudio は勝手に死ぬ

Windows 側の RDP オーディオエンドポイントが落ちると `/mnt/wslg/pulseaudio.log` に
`module-rdp-sink.c: data_send: send failed` が出て、以後サーバが応答しなくなる。
症状は2段階:

- **起動前に死んでいる** → `snd_pcm_open` が `Connection refused (111)` または
  30秒の `Timeout` で落ち、CLI が起動しない。復旧は `wsl.exe --shutdown`
  （＝WSL 全体の再起動）が確実。funkot 側では直せない
- **起動後に死ぬ** → ALSA pulse プラグインが以後ずっと `EIO` を返す。cpal の ALSA
  ワーカーはこの種のエラーをバックオフ無しで再試行するので、エラーコールバックが
  **実測 188万回/秒** 発火する。`d00884d` 以前は1コールバック1行を `eprintln!` して
  いたため 20秒放置で 720万行 / 648 MB が流れ、ターミナルが死んだ。
  `funkot-cli/src/stream_error.rs` で「2秒に1行へ集約 → 連発を検知したらストリームを
  破棄して黙る」に変更済み。今は3行出て止まり、`r` で再取得を試みる（10秒クールダウン）

音声デバイス無しで再現したいときは `snd_pcm_avail_delay` を `LD_PRELOAD` で `-EIO` に
差し替え、`~/.asoundrc` 相当を `pcm.!default { type null }` にすればよい
（実デバイス不要・実 libasound 経路のまま）。
