# ラベリング用ガイドクリックの位置決定

`--label-sections` は区間境界の候補位置にガイドクリックを重ねて再生する。
「クリックが音楽の小節頭で、かつ意図した小節数だけ手前で鳴る」ことは
ラベルの正しさの前提なので、ここに手を入れる前に本書を読むこと。

2026-07-28〜30 に3段階の位置ずれを潰した。**現行 HEAD は全14曲・全候補で
`lock_beat_phase` の移動量 ≤0.09拍**（＝ nominal がその場の実ビート格子にほぼ乗っている）。

| 症状 | 原因 | 対応 commit |
|---|---|---|
| クリックが小節の途中で鳴る | 候補を `total_frames` 生値から逆算（サブ拍位相が任意） | `b486a08` 位相ロック、`bbf684c` 小節格子アンカー |
| 曲によって拍が不安定 | fd 伝播格子のテンポドリフト（最大 0.49拍） | `0460891` テンポ refit |
| 残16小節のはずが残13小節 | **ファイル末尾 ≠ 音楽の終わり**（全曲に 0.64〜3.86小節のテール） | `33aac27` 音楽終端アンカー |
| フェードアウト曲だけ1小節late | 減衰の1小節目（−16 dB）を音楽と誤認（レベル閾値が緩すぎた） | 閾値調整（のち下の再設計で置換） |
| 終端の一撃が小節線にある曲で3拍late、フェード曲で1小節late | 「最後の一撃」の小節内位置から丸めていた（曲により上/下どちらにも丸めたい） | **リズム判定へ再設計**（`music_end_bar`） |
| Love & Joy だけ 1拍early（`bbed4d8` 後） | **曲の小節が `first_downbeat` 格子に対して途中でずれる**。アンカーは fd 格子の整数小節にしか置けないので表現できない | **小節位相の測定**（`outro_beat_phase_shift`、下の「小節位相のずれ」） |
| Eternal Light だけ 1小節late（位相補正後） | **音楽終端を fd 格子で解いてから拍を足していた**。答えが既に真の終端より上にある | **曲自身の格子で終端を測り直す**（下の「終端は曲自身の格子で解く」） |

## 現行方式（5層）

責務を分けてあり、**層をまたいで補正しないこと**が設計の肝。

1. **音楽終端アンカー**（`label_session.rs::music_end_bar`、`33aac27` → 2026-07-31 に再設計）
   アウトロ候補は「ファイル末尾」ではなく**音楽が終わる小節線**から数える。
   判定は「**4拍すべてにオンセットがある最後の小節**、その次の線」。
   走査する格子の位相は引数 `beat_phase` で受ける（層4が測った値。下の
   「終端は曲自身の格子で解く」）。
   広帯域スペクトルフラックス（`analysis::onset_flux_envelope`）を小節×4拍に割り、
   各小節の**最弱拍**がその曲の典型的な小節から `END_BEAT_ONSET_DB`（−16 dB）以内なら
   「リズムが走っている」とみなす。

   **「最後に叩かれた音」から丸める方式は破棄した**（2026-07-31、実耳2件で否定）。
   最後の一撃の小節内位置は曲によって上にも下にも丸めたく、単一の閾値では決まらない
   （実測: 切上げが要る 0.47、切下げが要る 0.23 と 0.65）。リズムが走っているか否かなら
   耳検証4曲すべてを**12 dB の余裕**で分離できる（最弱の「まだ鳴っている小節」が −10.2 dB、
   最強の「減衰だけの小節」が −22.5 dB。どちらも Kimi to Semi Blue）。
2. **整数小節への丸め**（`label_session.rs::outro_anchor_frame`、`bbf684c`）
   アンカーを `first_downbeat + round((anchor - fd) / bar_frames) × bar_frames` に
   丸め、`first_downbeat` の小節格子上に載せる。**丸めるのは整数小節数だけ**。
3. **テンポ refit**（`label_session.rs::outro_bar_frames_refit`、`0460891`）
   伝播に使う `bar_frames` をアウトロ局所のテンポで精密化する（下記）。
4. **小節位相の補正**（`label_session.rs::outro_beat_phase_shift`、2026-08-01）
   曲自身の小節が fd 格子に対してずれている分（0〜3拍）だけアンカーを後ろへ動かす。
   14曲中3曲が該当する。**この層だけが「拍」単位で動かす**（1・2は小節単位、
   3はテンポ、5は半拍未満）。詳細は下の「小節位相のずれ」。
   **層1は層4の答えを必要とし、層4は層1の暫定値を必要とする。** `click_grid` は
   これを2パスで解く: fd 格子（`beat_phase`=0）で暫定終端を出し、それを refit と
   位相測定の足場に使い、`shift`≠0 なら曲自身の格子で終端を**測り直す**。
   足場に使うだけなので暫定値が1小節ずれていても位相測定には影響しない。
5. **サブ拍位相ロック**（`analysis::lock_beat_phase` を再生窓そのものに適用、`b486a08`）
   広帯域スペクトルフラックスの全拍周期コム。`LOCK_CLEAR_WIN_RATIO=1.05` の
   明確勝ちのみ採用し、最後に `refine_kick_marker` でキック本体へスナップ。
   移動量は常に半拍未満なので、**この層が担当するのはサブ拍位相だけ**
   （AGENTS.md の「小節 identity をキック相関の ±N拍で取らない」に抵触しない）。
   イントロ側にも適用する（`first_downbeat` は 0.2拍ほどずれている曲がある）。

### テンポ refit の理屈と限界

`outro_bpm` の精度は約0.05%。577小節（Boom Boom Pow）伝播すると
0.04% × 2308拍 ≒ **半拍**になり、`lock_beat_phase` の探索半径を食い潰す。

アウトロ各候補を解析テンポでロックすると、局所的（ドリフト無し）かつ `fd` から
**整数拍**の位置が得られる。距離をその整数で割ればテンポが約0.001%精度で決まる。
5候補の**中央値**を採り、`REFIT_MIN_AGREEING_POINTS=3` 以上が残差 0.25拍以内で
一致し、かつ補正が `REFIT_MAX_REL_ADJUST=0.2%` 以内のときだけ採用（外れたら解析値のまま）。
小節 identity は触らない。

**限界**: 参照点は「ドリフトした nominal をロックして」得るので、**元のドリフトが
半拍未満のときだけ**真のテンポを回復できる。実測最大 0.49拍なので今の母集団では
成立しているが余裕は小さい。半拍を超えると参照点が隣の拍に吸着し、精密化された
テンポは「レバー長あたり1拍」長く出る。その結果は**内部的には一貫している**
（全候補が同じ格子に乗るので、1候補のクリックが正しいと確認できれば残りも信頼できる）が、
絶対的な拍 identity はこの証拠からは決められない。残差チェックでも判別不能。

## 測り方

`|shift|` = `lock_beat_phase` が nominal をどれだけ動かしたか。新アンカーの nominal は
定義上「格子上」にあるので、**shift は「伝播格子が局所の実ビートからどれだけ
ドリフトしたか」の直接測定**になる。アンカーやテンポ推定を触るときは
**14曲の `|shift|` を before/after で並べて回帰を見ること**。

```sh
# 補正量・アンカー・最後の一撃からの距離を出す
./dev.sh cargo run -p funkot-cli --release --example click_phase_diag -- \
  --cache-dir funkot-cache testdata/*.flac

# 4方式（local / prop / hybrid / refit）を並べる
./dev.sh cargo run -p funkot-cli --release --example outro_anchor_ab -- ...

# 素の音楽窓（クリック無し・ダック無し）を書き出す
./dev.sh cargo run -p funkot-cli --release -- \
  --label-sections -l LIST.txt --labels /dev/null --cache-dir funkot-cache \
  --render-clips OUT_DIR "--click-db=-200" --click-duck-db 0
```

**クリック位置は「クリック有り − クリック振幅ゼロ版」の差分で取る。**
合成後の信号だけを見て「クリックが埋もれている」「ここで鳴っている」と判断してはいけない。
クリック自身の減衰音とダック済み音楽を分離できないため
（`label_session.rs` の `clicks_stay_audible_over_dense_loud_material` がこの方式）。

## 試して失敗した方式（再挑戦しないこと）

1. **`first_downbeat + n × intro_bpm 拍` に丸めてサブ拍位相を決める** — 全長にわたる
   伝播で BPM 推定誤差が積もり、Boom Boom Pow では**半拍**ずれる。末尾が元々正しい曲を壊す。
   （層2の「整数小節への丸め」はこれとは別物。伝播格子を**整数小節の丸め**にしか使わず、
   累積誤差 最悪半拍 ≒ 0.125小節では丸め先の整数小節は揺るがない）
2. **末尾数小節（engine の `derive_outro_start_out` 相当）で groove refine** — Shirube /
   Sakura Photograph は末尾がフェード＝オンセットゼロで、ロック先が無い
3. **`refine_groove_phase` / `refine_periodic_phase`** — 探索が ±0.45拍に制限されており、
   IVY の +0.494拍（＝最悪の半拍あいまい点）には原理的に届かない
4. **低帯域（150Hz LPF）のオンセット novelty で全周期コム** — 密なミッドソング素材では
   同じ曲の窓ごとに互いに矛盾する位相を返す。**広帯域スペクトルフラックス**なら
   解析側の `first_downbeat` と数百分の1拍で一致する
5. **hybrid（サブ拍と拍 identity は局所アンカー、小節 identity だけ伝播格子から）**
   — あいまい点が lock の ±0.5拍から**小節スナップの ±2拍**に移るだけで、EOF 残差が
   半小節に近い曲（Shuki −0.415 / Love & Joy +0.495）で**丸1小節ずれる**。実測で Shuki は
   HEAD より 4.1拍手前の小節頭に落ちた。`examples/outro_anchor_ab.rs` に残してある
6. **レベル閾値だけで音楽終端を取る**（上昇判定なし）— 残響の途中で切るため Love & Joy で半小節遅れる。
   Shuki で合ったのは偶然
7. **オンセット + `round` で音楽終端の小節線を決める** — Shuki が 238小節になり実耳と1小節ずれる
8. **「最後の一撃」の小節内位置から丸める（`ceil` + slack）** — 耳検証4曲を同時に満たす
   slack が存在しない。Shuki は 0.47 を切上げ、Love & Joy は 0.23 を、Kimi は 0.65 を切下げたい。
   オンセット検出自体が減衰内で誤発火（+0.9拍、+2.6拍）したり最後の一撃を取りこぼしたり
   （−2.1拍）するので、**小数部は音楽的な量になっていない**
9. **相関のラグでスプライス位置を探す**（オンセット包絡の2小節窓を 3/4/5拍後と比較し、
   4拍以外が勝つ場所を探す）— 密な4つ打ちセクションでは包絡が1拍周期にほぼ乗るので
   3・4・5拍どれも高相関になり、勝者が雑音で決まる。Love & Joy では小節71〜270が
   一様に「ラグ3」になり、局所的な事件として何も出ない
10. **`music_end_bar` を拍解像度にする**（4つの位相それぞれで「4拍とも鳴っている最後の
   小節」を求め、最も後ろを採る）— フェードアウト曲が壊れる。Kimi to Semi Blue は
   減衰が −16 dB を数拍またいで超え続けるので、位相3が 379.3 まで伸びて正解 379.0 を
   1小節近く追い越す。**終端の数拍だけ見て小節位相は決められない**

#### フェードアウト曲では「テールの始まり」が音楽の終わり

上の表は「最後の一撃から EOF まで」だが、**フェードアウトする曲では減衰そのものが
まだ音楽に聞こえる**。判定閾値がこれを拾うと候補が丸1小節遅れる。

Sakura Photograph の小節ごとの RMS（EOF 直前、最大値基準）:

| 小節 | −7 | −6 | −5 | −4 | −3 | −2 | −1 |
|---|---|---|---|---|---|---|---|
| dB | −2.4 | −1.3 | **−16.1** | −24.7 | −31.5 | −41.6 | −49.1 |

フル音量は EOF の6小節前まで。閾値 −20 dB では −16.1 dB の小節を音楽と見なし
アンカーが `fd + 433小節` になり、**候補16が残15小節の位置で鳴った**（実耳報告）。
正しい終端は減衰の開始点 = `fd + 432小節`。

**閾値の感度（14曲を −24〜−6 dB で掃引）**: 13曲は全域で答えが変わらず、
**動くのはこのフェードアウト曲だけ**。−18 dB 以下で正解の 432 に収まるので、
プラトーの中央を取って **`TAIL_SILENCE_DB = −14 dB`** とした。
オンセット判定比 `TAIL_ONSET_RISE` は 1.6 のまま（2.0 にすると Monitoring Db /
Starmine / Moon Turtle / Kimi to Semi Blue / Love & Joy が動いてしまう）。

Shuki Shuki Song の実例: キックが EOF の 2.59小節前で止まる（50ms 窓の低域 RMS が
−25 → −46 → −60 dB と落ち、最後は完全な digital silence）。候補16の境界は EOF の
15.58小節前なので、音楽の終わりからは 15.58 − 2.59 ≒ **13小節** — ユーザーの実耳報告と一致。
`33aac27` でアンカーは `fd + 242小節` → `fd + 239小節`（報告どおりぴったり3小節）。

**「末尾40秒の RMS が −10〜−11 dBFS だから無音は無い」は誤り**（40秒平均では
2.5小節のテールが見えない）。50ms 窓で見ること。

## 小節位相のずれ

**曲自身の小節が、途中で `first_downbeat` 格子に対してずれることがある。**
どこかで1セクションが1拍短く（または長く）スプライスされている類で、
アウトロ側のクリックは全部そのずれを引きずる。14曲中3曲が該当する。

上の1〜3層はこれを表現できない。1と2は**小節単位**で動かし、3は**テンポ**を変える。
1拍という量はどれの出力空間にも無く、4層目の `lock_beat_phase` は半拍未満しか動かない。
Love & Joy の実耳報告2件が同じ物理位置を別の小節基準で言っていたのはそのため:

| | アンカー（fd格子） | 真の終端との差 | 実耳報告 |
|---|---|---|---|
| `bbed4d8` 前 | 341.00小節 | +3拍 | 「クリックが4拍目で鳴る」 |
| `bbed4d8` 後 | 340.00小節 | **−1拍** | 「1拍前にずれている」 |

真の終端は **fd + 340小節 + 1拍**。`bbed4d8` は小節数を1つ＝**4拍**動かしたので、
小節内の位相は原理的に変わりようがなかった。**直す軸が違っていた**。

### 測り方: 小節内の音量プロファイル

ダンス曲は小節頭の直前で抜くので、**小節の4拍目が最も静か**になる。
イントロ付近とアウトロ付近で曲を小節に畳み、最も静かな拍スロットが動いていれば、
動いた分だけ小節がずれている。**相対で測るのが肝**: 「4拍目が静かなはず」は
音楽的な仮定だが、「両端で同じスロットが静かなはず」は格子の性質であり、
いま疑っているのは格子そのものである。

- 窓は `PHASE_WINDOW_BARS`=48小節、両端 `PHASE_EDGE_BARS`=4小節を除く
- 最も静かなスロットが2番目より `PHASE_CLEAR_DB`=0.8 dB 下でなければ**棄権**して
  伝播格子をそのまま使う。14曲中5曲は少なくとも片側が判定不能（密なアレンジで
  小節に強弱の形が無い）。ノイズでスロットを選ぶより動かさない方が安全
- フラックスではなく**平均二乗**を使う。読んでいるのは「抜き」＝レベルの不在で、
  フラックスはそこを走り続けるハットを拾ってしまう

### 実耳検証（2026-08-01、4曲すべて一致）

`examples/outro_phase_ab` でアンカーを 0〜3拍ずらした同じクリップを4本書き、
「クリックが小節頭で鳴っているのはどれか」だけを答えてもらった:

| 曲 | ブロック列（16小節ごと・最も静かな拍） | 統計 | 実耳 |
|---|---|---|---|
| Monitoring Db | `333333.2.......111111` | +2拍 | **plus2** |
| Eternal Light | `333333333.......222222` | +3拍 | **plus3** |
| Love & Joy | `3333.............0000` | +1拍 | **plus1** |
| Kimi to Semi Blue | `333331333333.2333333333` | +0拍 | **plus0** |

残り10曲は +0拍または判定不能で、**この補正で動くのは上の3曲だけ**。
ずれる箇所そのものは特定できていない（Love & Joy の小節64〜279は4拍とも同音量の
密なセクションで、この統計では `.` が並ぶ）が、位置が判らなくても差は測れる。

### 終端は曲自身の格子で解く

上の実耳検証のあと、Eternal Light だけ「アウトロ入りクリックが1小節遅い」という
報告が残った（2026-08-01、ラベリング中）。**位相は合っていて小節が1つ違う**。

原因は層1と層4の**合成順序**だった。`music_end_bar` を fd 格子で解いてから
`shift` 拍を足すと、終端の一撃が fd 格子の最終小節の4拍目スロットを埋める曲では、
その小節が「まだ鳴っている」と読まれて答えが**真の終端より上に出る**。そこへさらに
拍を足すので、丸1小節後ろの線に着く。Eternal Light の末尾（`end_beat_diag`）:

| fd格子の拍 | 354.0 | 354.1 | 354.2 | 354.3 | 355.0 |
|---|---|---|---|---|---|
| RMS dB | −12.0 | −11.7 | −13.5 | −12.7 | **−36.0** |

真の終端は曲自身の小節線 **354.75**（＝ 354.3 の一撃がその線の上にあり、あとは減衰）。
fd 格子はここを小節 354 の4拍目としか呼べないので、小節 354 は4拍とも鳴っていることになり
`music_end_bar` は 355 を返す。+3拍して 355.75 — 1小節late。

**`shift`=1・2 では起きない。** 一撃の後ろに減衰しか無い拍が残るので、fd 格子の
最終小節が「4拍すべて」を満たさず、答えが上に出ない。Monitoring Db（+2）と
Love & Joy（+1）が実耳で合っていたのはこのため。

対応は、終端を**補正後の格子で測り直す**こと（`music_end_bar` の `beat_phase`）。
14曲の実測で動いたのは Eternal Light だけ（355.75 → **354.75**）、他13曲は出力不変。
`|shift|` も ≤0.069拍 に収まる（＝新アンカーが実ビート格子の上にある）。

#### 教訓: A/B クリップは小節 identity を問えない

`outro_phase_ab` の `plus0`〜`plus3` は**同じ小節の中の4つの拍**しか出さない。
「クリックが小節頭で鳴っているのはどれか」に正しく `plus3` と答えられても、
それが**正しい小節の頭か**はこの4本からは判らない（1小節ずれた同位相の位置は
どのクリップにも現れない）。位相の検証と小節数の検証は別に立てること。

もう一つのサイン: **アンカーが EOF の 0.011小節前**という値そのものがおかしい。
全曲に 0.64〜3.86小節のテールがあるという実測（下の表）と矛盾する。
修正後は 1.011小節になった。位相補正を入れたらこの距離を必ず見ること。

### 併せて否定された仮説

- **テンポドリフトではない**（`examples/beat_drift_diag`）。refit 後の周期で
  小節8と小節328のどちらも lock の移動量 ≒0.00拍。周期は正しく、fd からの
  拍数も整数。ずれているのは「どの拍を小節頭と呼ぶか」だけ
- **`music_end_bar` のリズム判定も正しい**（`examples/end_beat_diag`）。
  最後にリズムが走っている小節は合っている。問題は答えを整数小節にしか置けないこと

### AGENTS.md の禁止事項との関係

「小節 identity をキック相関の ±N拍で取らない」（→ [transition-phase.md](transition-phase.md)
v10 の失敗）に**抵触しない**。これは候補位置の周りで相関を探して勝った拍を選ぶのではなく、
48小節を畳んだ統計をイントロとアウトロで比較しているだけで、候補位置も遷移も見ていない。
とはいえ隣接領域なので、手を入れるなら v10 を読み直してから。

## 残っている懸念

- `lock_beat_phase` は**拍**にしか吸着せず、小節頭（mod-4）を見ない。アンカーが1拍以上
  ずれた曲では吸着先が小節頭でない拍になり得る。上の小節位相補正が入ったことで
  伝播格子由来のずれは消えたが、この層自体の性質は変わっていない
- **ミックス側のアウトロ整合は未確認。** エンジンの `outro_start_out` は fd からの
  伝播ではなく**ファイル終端**から逆算し（`analysis.rs` の「Production ends on a bar」）、
  そこに ±半拍のローカル refine と2仮説の選択が乗る。位相の出所が違うので、
  ここで測ったずれがそのまま効くとは限らない。テールが 0.64〜3.86小節ばらつくため
  この統計では判定できず、実ミックスを書き出して聴く（AGENTS.md「確認手順」）以外にない
