# ラベリング用ガイドクリックの位置決定

`--label-sections` は区間境界の候補位置にガイドクリックを重ねて再生する。
「クリックが音楽の小節頭で、かつ意図した小節数だけ手前で鳴る」ことは
ラベルの正しさの前提なので、ここに手を入れる前に本書を読むこと。

2026-07-28〜30 に3段階の位置ずれを潰した。**現行 HEAD は全14曲・全候補で
`lock_beat_phase` の移動量 ≤0.09拍**（＝ nominal がその場の実ビート格子にほぼ乗っている）。

| 症状 | 原因 | 対応 commit |
|---|---|---|
| クリックが小節の途中で鳴る | 候補を `total_frames` 生値から逆算（サブ拍位相が任意） | `b486a08` 位相ロック、`bbf684c` 小節格子アンカー |
| 曲によって拍が不安定 | fd 伝播格子のテンポドリフト（最大 0.49拍） | `0460891` テンポ refit |
| 残16小節のはずが残13小節 | **ファイル末尾 ≠ 音楽の終わり**（全曲に 0.64〜3.86小節のテール） | `33aac27` 音楽終端アンカー |
| フェードアウト曲だけ1小節late | 減衰の1小節目（−16 dB）を音楽と誤認（レベル閾値が緩すぎた） | 閾値調整（のち下の再設計で置換） |
| 終端の一撃が小節線にある曲で3拍late、フェード曲で1小節late | 「最後の一撃」の小節内位置から丸めていた（曲により上/下どちらにも丸めたい） | **リズム判定へ再設計**（`music_end_bar`） |
| Love & Joy だけ 1拍early（`bbed4d8` 後） | **曲の小節が `first_downbeat` 格子に対して途中でずれる**。アンカーは fd 格子の整数小節にしか置けないので表現できない | **小節位相の測定**（`outro_beat_phase_shift`、下の「小節位相のずれ」） |
| Eternal Light だけ 1小節late（位相補正後） | **音楽終端を fd 格子で解いてから拍を足していた**。答えが既に真の終端より上にある | **曲自身の格子で終端を測り直す**（下の「終端は曲自身の格子で解く」） |

## 現行方式（5層）

責務を分けてあり、**層をまたいで補正しないこと**が設計の肝。
6層目（側ごとの位相合意）は下の「裏拍へロックする」にある。

1. **音楽終端アンカー**（`label_session.rs::music_end_bar`、`33aac27` → 2026-07-31 に再設計）
   アウトロ候補は「ファイル末尾」ではなく**音楽が終わる小節線**から数える。
   判定は「**4拍すべてにオンセットがある最後の小節**、その次の線」。
   走査する格子の位相は引数 `beat_phase` で受ける（層4が測った値。下の
   「終端は曲自身の格子で解く」）。
   広帯域スペクトルフラックス（`analysis::onset_flux_envelope`）を小節×4拍に割り、
   各小節の**最弱拍**がその曲の典型的な小節から `END_BEAT_ONSET_DB`（−16 dB）以内なら
   「リズムが走っている」とみなす。

   **「最後に叩かれた音」から丸める方式は破棄した**（2026-07-31、実耳2件で否定）。
   最後の一撃の小節内位置は曲によって上にも下にも丸めたく、単一の閾値では決まらない
   （実測: 切上げが要る 0.47、切下げが要る 0.23 と 0.65）。リズムが走っているか否かなら
   耳検証4曲すべてを**12 dB の余裕**で分離できる（最弱の「まだ鳴っている小節」が −10.2 dB、
   最強の「減衰だけの小節」が −22.5 dB。どちらも Kimi to Semi Blue）。
2. **整数小節への丸め**（`label_session.rs::outro_anchor_frame`、`bbf684c`）
   アンカーを `first_downbeat + round((anchor - fd) / bar_frames) × bar_frames` に
   丸め、`first_downbeat` の小節格子上に載せる。**丸めるのは整数小節数だけ**。
3. **テンポ refit**（`label_session.rs::outro_bar_frames_refit`、`0460891`）
   伝播に使う `bar_frames` をアウトロ局所のテンポで精密化する（下記）。
4. **小節位相の補正**（`label_session.rs::outro_beat_phase_shift`、2026-08-01、
   棄権ゲートは 2026-08-04）
   曲自身の小節が fd 格子に対してずれている分（0〜3拍）だけアンカーを後ろへ動かす。
   14曲中3曲が該当する。**この層だけが「拍」単位で動かす**（1・2は小節単位、
   3はテンポ、5は半拍未満）。**イントロ窓の最も静かなスロットが 3 以外なら棄権する**
   （下の「決着: どちらの形でもなく、棄権ゲート」）。詳細は下の「小節位相のずれ」。
   **層1は層4の答えを必要とし、層4は層1の暫定値を必要とする。** `click_grid` は
   これを2パスで解く: fd 格子（`beat_phase`=0）で暫定終端を出し、それを refit と
   位相測定の足場に使い、`shift`≠0 なら曲自身の格子で終端を**測り直す**。
   足場に使うだけなので暫定値が1小節ずれていても位相測定には影響しない。
5. **サブ拍位相ロック**（`analysis::lock_beat_phase` を再生窓そのものに適用、`b486a08`）
   広帯域スペクトルフラックスの全拍周期コム。`LOCK_CLEAR_WIN_RATIO=1.05` の
   明確勝ちのみ採用し、最後に `refine_kick_marker` でキック本体へスナップ。
   移動量は常に半拍未満なので、**この層が担当するのはサブ拍位相だけ**
   （AGENTS.md の「小節 identity をキック相関の ±N拍で取らない」に抵触しない）。
   イントロ側にも適用する（`first_downbeat` は 0.2拍ほどずれている曲がある）。

### テンポ refit の理屈と限界

`outro_bpm` の精度は約0.05%。577小節（Boom Boom Pow）伝播すると
0.04% × 2308拍 ≒ **半拍**になり、`lock_beat_phase` の探索半径を食い潰す。

アウトロ各候補を解析テンポでロックすると、局所的（ドリフト無し）かつ `fd` から
**整数拍**の位置が得られる。距離をその整数で割ればテンポが約0.001%精度で決まる。
5候補の**中央値**を採り、`REFIT_MIN_AGREEING_POINTS=3` 以上が残差 0.25拍以内で
一致し、かつ補正が `REFIT_MAX_REL_ADJUST=0.2%` 以内のときだけ採用（外れたら解析値のまま）。
小節 identity は触らない。

**限界**: 参照点は「ドリフトした nominal をロックして」得るので、**参照点が真の拍に
乗っているときだけ**真のテンポを回復できる。乗り損なうと、その**定数オフセットが
レバー長で割られて周期の誤りに化ける**。結果は**内部的には一貫している**
（全候補が同じ格子に乗るので、1候補のクリックが正しいと確認できれば残りも信頼できる）
が、絶対的な拍 identity はこの証拠からは決められない。残差チェックでも
`REFIT_MAX_REL_ADJUST` でも判別不能。

**この限界は「元のドリフトが半拍を超えたとき」だけではない。** 当初は
「半拍を超えると参照点が隣の拍に吸着する」と書いていたが、`Kamurogiku` では
**元のドリフトが 0.218拍でも**参照点が裏拍へ吸着し、周期が +0.0243% 長く出た
（下の「refit が裏拍を周期の誤りに化かす」）。**引き金はドリフト量ではなく、
その曲のコムが裏拍を選ぶかどうか**である。

## 測り方

`|shift|` = `lock_beat_phase` が nominal をどれだけ動かしたか。新アンカーの nominal は
定義上「格子上」にあるので、**shift は「伝播格子が局所の実ビートからどれだけ
ドリフトしたか」の直接測定**になる。アンカーやテンポ推定を触るときは
**14曲の `|shift|` を before/after で並べて回帰を見ること**。

```sh
# 補正量・アンカー・最後の一撃からの距離を出す
./dev.sh cargo run -p funkot-cli --release --example click_phase_diag -- \
  --cache-dir funkot-cache testdata/*.flac

# 4方式（local / prop / hybrid / refit）を並べる
./dev.sh cargo run -p funkot-cli --release --example outro_anchor_ab -- ...

# コムが表拍と裏拍のどちらを選んだか（--dump-bar N で1窓分の曲線を出す）
./dev.sh cargo run -p funkot-cli --release --example offbeat_diag -- \
  --cache-dir funkot-cache --step 8 --half-width 8 testdata/*.flac

# 全長でロックの移動量を追う（ランプ＝周期が違う、飛び＝裏拍）
./dev.sh cargo run -p funkot-cli --release --example beat_drift_diag -- \
  --cache-dir funkot-cache --step 8 testdata/TRACK.flac

# 素の音楽窓（クリック無し・ダック無し）を書き出す
./dev.sh cargo run -p funkot-cli --release -- \
  --label-sections -l LIST.txt --labels /dev/null --cache-dir funkot-cache \
  --render-clips OUT_DIR "--click-db=-200" --click-duck-db 0
```

**クリック位置は「クリック有り − クリック振幅ゼロ版」の差分で取る。**
合成後の信号だけを見て「クリックが埋もれている」「ここで鳴っている」と判断してはいけない。
クリック自身の減衰音とダック済み音楽を分離できないため
（`label_session.rs` の `clicks_stay_audible_over_dense_loud_material` がこの方式）。

## 試して失敗した方式（再挑戦しないこと）

1. **`first_downbeat + n × intro_bpm 拍` に丸めてサブ拍位相を決める** — 全長にわたる
   伝播で BPM 推定誤差が積もり、Boom Boom Pow では**半拍**ずれる。末尾が元々正しい曲を壊す。
   （層2の「整数小節への丸め」はこれとは別物。伝播格子を**整数小節の丸め**にしか使わず、
   累積誤差 最悪半拍 ≒ 0.125小節では丸め先の整数小節は揺るがない）
2. **末尾数小節（engine の `derive_outro_start_out` 相当）で groove refine** — Shirube /
   Sakura Photograph は末尾がフェード＝オンセットゼロで、ロック先が無い
3. **`refine_groove_phase` / `refine_periodic_phase`** — 探索が ±0.45拍に制限されており、
   IVY の +0.494拍（＝最悪の半拍あいまい点）には原理的に届かない
4. **低帯域（150Hz LPF）のオンセット novelty で全周期コム** — 密なミッドソング素材では
   同じ曲の窓ごとに互いに矛盾する位相を返す。**広帯域スペクトルフラックス**なら
   解析側の `first_downbeat` と数百分の1拍で一致する
5. **hybrid（サブ拍と拍 identity は局所アンカー、小節 identity だけ伝播格子から）**
   — あいまい点が lock の ±0.5拍から**小節スナップの ±2拍**に移るだけで、EOF 残差が
   半小節に近い曲（Shuki −0.415 / Love & Joy +0.495）で**丸1小節ずれる**。実測で Shuki は
   HEAD より 4.1拍手前の小節頭に落ちた。`examples/outro_anchor_ab.rs` に残してある
6. **レベル閾値だけで音楽終端を取る**（上昇判定なし）— 残響の途中で切るため Love & Joy で半小節遅れる。
   Shuki で合ったのは偶然
7. **オンセット + `round` で音楽終端の小節線を決める** — Shuki が 238小節になり実耳と1小節ずれる
8. **「最後の一撃」の小節内位置から丸める（`ceil` + slack）** — 耳検証4曲を同時に満たす
   slack が存在しない。Shuki は 0.47 を切上げ、Love & Joy は 0.23 を、Kimi は 0.65 を切下げたい。
   オンセット検出自体が減衰内で誤発火（+0.9拍、+2.6拍）したり最後の一撃を取りこぼしたり
   （−2.1拍）するので、**小数部は音楽的な量になっていない**
9. **相関のラグでスプライス位置を探す**（オンセット包絡の2小節窓を 3/4/5拍後と比較し、
   4拍以外が勝つ場所を探す）— 密な4つ打ちセクションでは包絡が1拍周期にほぼ乗るので
   3・4・5拍どれも高相関になり、勝者が雑音で決まる。Love & Joy では小節71〜270が
   一様に「ラグ3」になり、局所的な事件として何も出ない
10. **`music_end_bar` を拍解像度にする**（4つの位相それぞれで「4拍とも鳴っている最後の
   小節」を求め、最も後ろを採る）— フェードアウト曲が壊れる。Kimi to Semi Blue は
   減衰が −16 dB を数拍またいで超え続けるので、位相3が 379.3 まで伸びて正解 379.0 を
   1小節近く追い越す。**終端の数拍だけ見て小節位相は決められない**

#### フェードアウト曲では「テールの始まり」が音楽の終わり

上の表は「最後の一撃から EOF まで」だが、**フェードアウトする曲では減衰そのものが
まだ音楽に聞こえる**。判定閾値がこれを拾うと候補が丸1小節遅れる。

Sakura Photograph の小節ごとの RMS（EOF 直前、最大値基準）:

| 小節 | −7 | −6 | −5 | −4 | −3 | −2 | −1 |
|---|---|---|---|---|---|---|---|
| dB | −2.4 | −1.3 | **−16.1** | −24.7 | −31.5 | −41.6 | −49.1 |

フル音量は EOF の6小節前まで。閾値 −20 dB では −16.1 dB の小節を音楽と見なし
アンカーが `fd + 433小節` になり、**候補16が残15小節の位置で鳴った**（実耳報告）。
正しい終端は減衰の開始点 = `fd + 432小節`。

**閾値の感度（14曲を −24〜−6 dB で掃引）**: 13曲は全域で答えが変わらず、
**動くのはこのフェードアウト曲だけ**。−18 dB 以下で正解の 432 に収まるので、
プラトーの中央を取って **`TAIL_SILENCE_DB = −14 dB`** とした。
オンセット判定比 `TAIL_ONSET_RISE` は 1.6 のまま（2.0 にすると Monitoring Db /
Starmine / Moon Turtle / Kimi to Semi Blue / Love & Joy が動いてしまう）。

Shuki Shuki Song の実例: キックが EOF の 2.59小節前で止まる（50ms 窓の低域 RMS が
−25 → −46 → −60 dB と落ち、最後は完全な digital silence）。候補16の境界は EOF の
15.58小節前なので、音楽の終わりからは 15.58 − 2.59 ≒ **13小節** — ユーザーの実耳報告と一致。
`33aac27` でアンカーは `fd + 242小節` → `fd + 239小節`（報告どおりぴったり3小節）。

**「末尾40秒の RMS が −10〜−11 dBFS だから無音は無い」は誤り**（40秒平均では
2.5小節のテールが見えない）。50ms 窓で見ること。

## 小節位相のずれ

**曲自身の小節が、途中で `first_downbeat` 格子に対してずれることがある。**
どこかで1セクションが1拍短く（または長く）スプライスされている類で、
アウトロ側のクリックは全部そのずれを引きずる。14曲中3曲が該当する。

上の1〜3層はこれを表現できない。1と2は**小節単位**で動かし、3は**テンポ**を変える。
1拍という量はどれの出力空間にも無く、4層目の `lock_beat_phase` は半拍未満しか動かない。
Love & Joy の実耳報告2件が同じ物理位置を別の小節基準で言っていたのはそのため:

| | アンカー（fd格子） | 真の終端との差 | 実耳報告 |
|---|---|---|---|
| `bbed4d8` 前 | 341.00小節 | +3拍 | 「クリックが4拍目で鳴る」 |
| `bbed4d8` 後 | 340.00小節 | **−1拍** | 「1拍前にずれている」 |

真の終端は **fd + 340小節 + 1拍**。`bbed4d8` は小節数を1つ＝**4拍**動かしたので、
小節内の位相は原理的に変わりようがなかった。**直す軸が違っていた**。

### 測り方: 小節内の音量プロファイル

ダンス曲は小節頭の直前で抜くので、**小節の4拍目が最も静か**になる。
イントロ付近とアウトロ付近で曲を小節に畳み、最も静かな拍スロットが動いていれば、
動いた分だけ小節がずれている。**相対で測るのが肝**: 「4拍目が静かなはず」は
音楽的な仮定だが、「両端で同じスロットが静かなはず」は格子の性質であり、
いま疑っているのは格子そのものである。

- 窓は `PHASE_WINDOW_BARS`=48小節、両端 `PHASE_EDGE_BARS`=4小節を除く
- 最も静かなスロットが2番目より `PHASE_CLEAR_DB`=0.8 dB 下でなければ**棄権**して
  伝播格子をそのまま使う。14曲中5曲は少なくとも片側が判定不能（密なアレンジで
  小節に強弱の形が無い）。ノイズでスロットを選ぶより動かさない方が安全
- フラックスではなく**平均二乗**を使う。読んでいるのは「抜き」＝レベルの不在で、
  フラックスはそこを走り続けるハットを拾ってしまう

### 終端は曲自身の格子で解く

上の実耳検証のあと、Eternal Light だけ「アウトロ入りクリックが1小節遅い」という
報告が残った（2026-08-01、ラベリング中）。**位相は合っていて小節が1つ違う**。

原因は層1と層4の**合成順序**だった。`music_end_bar` を fd 格子で解いてから
`shift` 拍を足すと、終端の一撃が fd 格子の最終小節の4拍目スロットを埋める曲では、
その小節が「まだ鳴っている」と読まれて答えが**真の終端より上に出る**。そこへさらに
拍を足すので、丸1小節後ろの線に着く。Eternal Light の末尾（`end_beat_diag`）:

| fd格子の拍 | 354.0 | 354.1 | 354.2 | 354.3 | 355.0 |
|---|---|---|---|---|---|
| RMS dB | −12.0 | −11.7 | −13.5 | −12.7 | **−36.0** |

真の終端は曲自身の小節線 **354.75**（＝ 354.3 の一撃がその線の上にあり、あとは減衰）。
fd 格子はここを小節 354 の4拍目としか呼べないので、小節 354 は4拍とも鳴っていることになり
`music_end_bar` は 355 を返す。+3拍して 355.75 — 1小節late。

**`shift`=1・2 では起きない。** 一撃の後ろに減衰しか無い拍が残るので、fd 格子の
最終小節が「4拍すべて」を満たさず、答えが上に出ない。Monitoring Db（+2）と
Love & Joy（+1）が実耳で合っていたのはこのため。

対応は、終端を**補正後の格子で測り直す**こと（`music_end_bar` の `beat_phase`）。
14曲の実測で動いたのは Eternal Light だけ（355.75 → **354.75**）、他13曲は出力不変。
`|shift|` も ≤0.069拍 に収まる（＝新アンカーが実ビート格子の上にある）。

#### 教訓: A/B クリップは小節 identity を問えない

`phase_ab` の `plus0`〜`plus3` は**同じ小節の中の4つの拍**しか出さない。
「クリックが小節頭で鳴っているのはどれか」に正しく `plus3` と答えられても、
それが**正しい小節の頭か**はこの4本からは判らない（1小節ずれた同位相の位置は
どのクリップにも現れない）。位相の検証と小節数の検証は別に立てること。

**さらに、整数拍4本は「ずれが整数拍である」ことを前提にしている。** 格子ごと
半拍ずれた曲では4本とも裏拍になり、正解が一度も現れない（`Kamurogiku`、
下の「refit が裏拍を周期の誤りに化かす」）。**「どれも表拍でない」は答えのうち**
として扱い、`--offsets 0.5,1.5,2.5,3.5` で半拍位置を出し直すこと。
`phase_ab` の `--offsets` は小数拍を受ける（既定は `0,1,2,3`）。

もう一つのサイン: **アンカーが EOF の 0.011小節前**という値そのものがおかしい。
全曲に 0.64〜3.86小節のテールがあるという実測（下の表）と矛盾する。
修正後は 1.011小節になった。位相補正を入れたらこの距離を必ず見ること。

## 裏拍へロックする（2026-08-02 発見・対処済み、実耳確認待ち）

**`lock_beat_phase` のコムは周期が1拍なので、表拍と裏拍を区別できない。** 曲によっては
窓の1〜2割で裏拍が `LOCK_CLEAR_WIN_RATIO`=1.05 を超えて勝つ。上の14曲では
2点以下に留まっていたので表面化しなかった。生データは
[testdata/offbeat_lock_diag.md](../testdata/offbeat_lock_diag.md)。

`Alvian - … - 15 Yao Bu Neng Ting`（White Label 2025 Fall）で顕在化した。実耳報告は
「わずかに小節頭よりクリックが遅い」。

- 8小節ごとに全長を走査すると **44点中10点が +0.41〜+0.45拍**（= 0.5 − キック
  リファインの系統バイアス 0.06 = 裏拍そのもの）。残り34点は ≤0.08 で**ランプが無い**
  ＝解析周期は全長で正しい。ずれは周期でもスプライスでもなく**ロックの相手違い**
- `outro_bar_frames_refit` の参照点5つのうち**3つが裏拍**に落ちた。中央値がその塊を
  拾い、周期が **+0.0376%** 長くなる。`REFIT_MAX_REL_ADJUST`（0.2%）にも
  残差0.25拍・3点一致にも掛からない
- 結果、**アウトロ5候補すべてが遅れる**。32/48/64 は +0.42拍（≒150ms）、
  8/16 は refit 後の nominal が真の拍のちょうど中間に来るためロックが上へ倒れて**+1拍**。
  イントロ側は refit を通らないが `intro 32` は単独で +0.45拍

### `|shift|` は poisoned refit を検出できない

上の「測り方」の回帰指標は、**refit が動いた曲では意味を失う**。refit は参照点が
合意した位相へ nominal 自体を動かすので、裏拍に落ちた候補ほど `shift` が 0 に近づく。
Alvian で壊れている 32/48/64 の `shift` は −0.11 / −0.01 / +0.01、正しい位置へ
引き戻された 8/16 が +0.47 と出る。**符号が逆に読める。**
`shift` を見る前に、その曲の refit 補正量と `beat_drift_diag` のランプの有無を見ること。

### 層6: 側ごとの位相合意（`side_lock_offset` / `branch_indices`）

**同じ側の候補は全部が同じサブ拍位相に乗るべき**という不変条件を明示的に課した。
候補は同じ伝播格子の上で互いに整数拍離れているので、正しいロックなら移動量は
（散らばりを除いて）全候補で同じになる。

- 各候補を独立にロックしてオフセット（`locked - nominal`、frames）を集める。
  窓が音源の外へ出る候補は**捨てる**（`lock_boundary_to_groove` はそこで nominal を
  そのまま返し、偽の「オフセット0」になる）
- 中央値から `BRANCH_SPLIT_BEATS`=0.25拍 以上外れた点を別の枝とみなす
- 2つの枝の中央値が**半拍離れている**なら（`BRANCH_HALF_BEAT_TOL`=0.15拍以内で
  0.5拍に一致）表裏の割れと読み、**nominal 格子に近い方**（`|中央値|` の小さい方）を採る。
  半拍でなければ単なる散らばりとみなし多数側を残す
- **どの点も中央値の 0.25拍以内に来ないときは棄権する**（`None`）。偶数個のとき中央値は
  中央2値の平均なので、0.5拍以上離れた2点が中央値を挟むと全点が band の外に出る。
  これは表裏の割れではなく読めない散らばりなので、合意を作らず候補自身のロックを残す。
  谷の位置に合意値を置くと**全候補を巻き込んで動かして**しまう
- 候補の最終位置は、自分のロックが合意から 0.25拍以上外れたときだけ合意値に置き換える。
  **合っている候補は自分のロック結果のまま**（合意値との差は実測 0.05拍程度あり、
  一律に均すと今まで正しく鳴っていた位置まで動く）
- `outro_bar_frames_refit` の参照点にも同じ判定を掛ける。裏拍の点は
  `REFIT_MAX_RESIDUAL_BEATS` に掛からない（裏拍も「どこかの整数拍」の 0.25拍以内に
  居る）ので、この判定でしか落とせない

**多数決にしない。** Alvian はアウトロ5点中3点が裏拍側で、多数決なら誤る方を選ぶ。
判断基準は「伝播格子＝解析器が決めた小節頭にどちらが近いか」であって票数ではない。
ロックはサブ拍位相の層であり、小節頭を半拍ひっくり返す権限を持たない（層5の議論）。

**既知の限界**: 真の位相が伝播格子から 0.25拍以上ずれていて、かつ裏拍汚染もある曲では
逆の枝を選ぶ。実測31曲の一様オフセットは最大 0.40拍（DEKZ - Dora Dora の −0.36）で、
そういう曲は枝が割れないため発火しない。構造的に排除されてはいない。

**却下した案**: (a) `LOCK_CLEAR_WIN_RATIO` を上げる — 現行のゲートは勝者を
**delta 0 と**比べるが、delta 0 は2つのピークの**谷**にある（格子自体が 0.06〜0.07拍
ずれているため）ので `best/zero` は全窓で 2.7〜5.6 になり、閾値として意味を成さない。
(b) 低域（キック）で二択を割る — 曲線を出すと低域のピークは表拍とも裏拍とも一致しない
窓がある（Alvian 小節176 で −0.40拍）。判別器にならない。`offbeat_diag --dump-bar` で見られる

## 小節位相の測定が White Label で破綻する（2026-08-03 発覚 → 2026-08-04 決着）

**結論は下の「決着: どちらの形でもなく、棄権ゲート」。** イントロ窓が 3 以外を
明確に返したら棄権する。`Dora Dora`（棄権のまま取りこぼす側）は**未解決**。

`DEKZ - Dora Dora` のアウトロで「**4拍めにクリックがある**」というラベリング報告が出た。
生データは [testdata/bar_phase_survey_31.md](../testdata/bar_phase_survey_31.md)。
**Dora Dora 単体の不具合ではなく、`outro_beat_phase_shift` の定式化そのものが
テストセット14曲では検証不能だった**ことが分かった。

### 何が起きたか（Dora Dora）

小節128 あたりに**編集点**がある。`beat_drift_diag` のロック移動量は小節112 まで
0.00 で平坦、小節128 で −0.35拍へ落ち、以降末尾まで平坦。**ランプではなく段差**なので
テンポドリフトではない。折り畳みの最も静かなスロットは小節0〜100 で 3（格子が合っている）、
120〜190 で 1、200〜末尾で 0 と動く。アウトロ候補は全部その最後の領域に居るので、
**正しい補正は +1拍**。

`outro_beat_phase_shift` は**両側とも 0.8 dB に届かず棄権**した（48小節窓は、
互いに食い違う区画を平均するので洗い流される）。補正 0 のまま、クリックは1拍手前
＝音楽の4拍めで鳴る。実耳報告と一致する。

サブ拍層は無関係で、**全候補のロック移動量は ≤0.09拍**。壊れているのは
「どの拍を小節頭と呼ぶか」だけ。イントロ側の候補（〜96小節）は編集点より手前に
あるので正しく鳴る — ラベル行の `intro_best` だけが埋まっているのと整合する。

なお `outro_bar_frames_refit` はこの段差を **−0.0232%** の周期変更として**吸収している**。
`REFIT_MAX_REL_ADJUST`（0.2%）にも残差 0.25拍にも掛からない。アウトロ候補は段差より
後ろの平坦域に揃うので実害は出ていないが、**refit の前提（ずれは周期の誤りである）は
この曲では成立していない**。

### 定式化の問題: 相対と絶対が母集団で区別できていなかった

`shift = (q_outro − q_intro) mod 4` は、`q_intro = 3` のとき
絶対形 `(q_outro + 1) mod 4` と**恒等的に等しい**（−3 ≡ +1 mod 4）。
そして**テストセット14曲のイントロ窓は 9曲が 3、5曲が判定不能で、3 以外は一つも無い**。
つまり相対形は、絶対形と答えが違うケースに一度も当たらないまま採用されていた。

White Label 17曲には違うケースがある。`YSR - 01 Andai Tak Berpisah` は
**intro 0（+1.1 dB）/ outro 3（+0.9 dB）→ shift +3 を適用する**。しかし
アウトロ窓の 3 はダンスマスターの想定どおりの読みで、**格子は合っている**。
絶対形なら補正 0。相対形はここで**合っている格子を3拍動かして壊す**。
`click_phase_diag` のアンカーが `bar 534.75 from fd` と .75 になっているのがその適用跡。
**次にこの曲をラベリングすると、Dora Dora と同じ「4拍めで鳴る」が出るはず**
（ただし原因は逆で、補正しなかったからではなく補正したから）。

相対形にも守っているものはある。「小節の4拍目が最も静か」は音楽的な仮定なので、
その仮定に従わない曲で絶対形は偽の補正を出す。相対形はそこを 0 に落とす。
**両者は別の失敗モードを持ち、この母集団には両方の曲が居る。**

### 決着: どちらの形でもなく、棄権ゲート（2026-08-04、実耳）

A/B クリップの実耳結果（生データは
[testdata/phase_ab_results.md](../testdata/phase_ab_results.md)）で
**相対形も絶対形も単独では否定された**。答えの出た2曲はどちらも**正しい補正が 0**
で、各形式がそれぞれ片方を壊す:

| 曲 | イントロ窓 | アウトロ窓 | 相対形 | 絶対形 | 実耳 |
|---|---|---|---|---|---|
| `YSR - 01 Andai Tak Berpisah` | 0（+1.1 dB） | 3（+0.9 dB） | **+3 ✗** | 0 ✓ | **0** |
| `DimsR - 04 Kamurogiku` | unclear | 0（+1.7 dB） | 0 ✓ | **+1 ✗** | **0** |

採用したのは上で候補に挙げていた**棄権ゲート**:
**イントロ窓が 3 以外を明確に返したら補正を出さない。** 2曲とも正解になる。
実装済み（`outro_beat_phase_shift` の `qi == BEATS_PER_BAR - 1` ガード、
`bar_phase_diag` の verdict も棄権を明示する）。60曲の before/after は
`testdata/bar_phase_survey_60{,_after}.txt` で、**差分は `Andai` の1行のみ**。

#### クリック格子への影響（60曲、`click_phase_diag` before/after）

`bar_phase_diag` は測定値、こちらは**実際にクリックが鳴る位置**。生データは
`testdata/click_phase_survey_60{_before,_after}.txt`。**動いたのは `Andai` の
アウトロ5候補だけで、残り59曲は1フレームも動かない**（イントロ側はゲートの
対象外なので当然動かない）。

|---|---|---|
| 音楽終端 | EOF の 1.243小節前、`bar 534.75` | EOF の 0.993小節前、**`bar 535.00`** |
| 候補 8小節 | −0.0351 | −0.0808 |
| 候補 16小節 | −0.0361 | **+0.0128** |
| 候補 32小節 | −0.0485 | **+0.0106** |
| 候補 48小節 | **−0.2071** | **+0.0084** |
| 候補 64小節 | +0.0056 | +0.0041 |

−0.21拍からほぼ 0 になったのは、ロックが格子の誤りを引き戻していたのが
消えたということ（層6の署名と同じ読み方）。

**ゲートを入れると式の選択という問題自体が消える。** `qi = 3` の下では
`(qo − qi) mod 4` と `(qo + 1) mod 4` は恒等なので、ゲートを通った曲では
相対形と絶対形は必ず同じ答えを出す。式は相対形のまま残してある
（ゲートを緩めるときに何を緩めるのかが見えるように）。

母集団60曲で挙動が変わるのは **`Andai` の1曲だけ**（イントロ窓が 3 以外を
明確に返す唯一の曲）。実耳検証済みの4曲と、`+1` を出す `Love & Joy` 署名の3曲は
いずれもイントロ窓が 3 なので影響を受けない。

`Andai` の intro 側も `plus0` が正解だった。**イントロ窓の 0 は格子のずれではなく
アレンジ**という下節の読みが、そのまま実耳で裏付けられた形になる。

### イントロ窓の読みは信用できない

`Kekka Orai` と `Andai` はイントロ領域で 0、アウトロ領域で 3 を返す。しかし
**最も静かなスロットは動くのに最も大きいスロットは 2 のまま動かない**（生データ §5）。
剛体回転ならどちらも同じだけ回る。回っていないので、これは格子のずれではなく
**イントロ素材のアレンジ**（頭の数十小節は「小節頭の直前で抜く」形になっていない）
である可能性が高い。`PHASE_EDGE_BARS`=4 では曲頭の性格の違うセクションを外し切れない。

Dora Dora も厳密な剛体回転ではない（イントロ quiet3/loud1 → アウトロ quiet0/loud3）。
**この統計は元々そこまで強くない**ことを、手を入れる前に見込んでおくこと。

### 60曲へ拡張して分かったこと（2026-08-03）

`file_list.txt` が60曲になった時点で測り直した。**補正が実際に適用されるのは8曲**、
**棄権が30曲**。生データは [testdata/bar_phase_survey.md](../testdata/bar_phase_survey.md) §0。

**新たに3曲（`Refanda` / `Rofi Spenzha` / `06. Street Runway`）が `+1` を出す。**
いずれも「イントロ窓が明確に 3、アウトロ窓が明確に 0」という **Love & Joy と同じ署名**で、
Love & Joy はその署名で実耳一致している。**両窓が明確に読めたときの測定は信用してよい**
という方向の材料。偽補正の疑いがあるのは、依然として**イントロ窓が 3 以外を返した
`Andai` だけ**（60曲でこの1曲）。

#### `Kamurogiku` — 折り畳みの読みが「壊れた格子の上で」出た例（2026-08-04 解決）

```
DimsR - Gakumas no Remix - 04 Kamurogiku       00100000000000000
    intro unclear       | outro quiet 0 (+1.7 dB) | no verdict
```

**17区画中16区画が 0** なので当初は「`first_downbeat` が1拍ずれている初めての例」
（＝絶対形が正しいことの決定的証拠）と読んだ。**この読みは誤りだった。**

実耳では**補正 0 が正しい**（絶対形の `+1` は偽補正）。fd の**小節 identity は
合っている**。実際にずれていたのは小節位相ではなく**サブ拍位相で、しかも半拍**
（下の「refit が裏拍を周期の誤りに化かす」）。

**折り畳みは、半拍ずれた格子の上で測っていた。** スロット境界が真の拍を跨ぐので、
この曲の `0` という読みは小節位相の証拠にならない。**折り畳みの答えを信じてよいのは
その格子のサブ拍位相が正しいときだけ**という、これまで明文化していなかった前提が
ここで表に出た。`Kamurogiku` を判別力の高いケースとして扱ったのが誤りで、
定式化を決めたのは結局 `Andai` の側だった。

### 既存ラベルへの影響

**小節の間隔は変わらないので、記録済みの小節数は読み直さなくてよい。** 壊れるのは

## refit が裏拍を周期の誤りに化かす（2026-08-04 発見、未修正）

`Kamurogiku` のアウトロは A/B の**整数拍4本がすべて裏拍**で鳴っていた。
半拍を足した4本を出して初めて表拍に乗り、**正解は現行格子の −0.5拍**。
生データと逆算は [testdata/phase_ab_results.md](../testdata/phase_ab_results.md)。

### 数字

実耳の2点（intro 16小節、outro の小節頭）から真の格子を出すと:

| | 周期（フレーム/拍） | 真の値との差 |
|---|---|---|
| 真（実耳2点から） | 14699.97 | — |
| 解析 `outro_bpm` 由来 | 14699.81 | **−0.0011%**（ほぼ完全） |
| 解析 `intro_bpm` 由来 | 14696.20 | −0.0257% |
| **refit 後（現行）** | **14703.55** | **+0.0243%** |

ずれ 0.491拍の内訳は**ちょうど半々の2つの和**:

- `first_downbeat` が真の小節頭より **0.230拍 遅い**（イントロ側はロックが吸収する）
- refit が周期を +0.0243% 長くした ＝ 1072拍で **0.261拍**

**この曲にテンポの問題は無かった。** 解析値は 0.001% 精度で当たっており、
refit だけが 10倍以上に悪化させている。

### 何が起きたか

1. アウトロ領域で**コムが裏拍のピークを選ぶ**。refit 前の格子はまだ +0.218拍 しか
   ずれておらず、表拍へ −0.22 引き戻すことも半径内で可能だったのに、+0.28 動かして
   裏拍へ乗せた
2. `outro_bar_frames_refit` は参照点が真の拍に乗っている前提なので、**一様な半拍の
   オフセットをレバー長で割って周期の誤りに化かす**。5候補が全部 +0.5拍 裏拍だと
   仮定して逆算した周期は 14703.57〜14704.48 で、**実際の refit 値 14703.553 と
   0.002% 以内で一致する**。残差 0.25拍 にも `REFIT_MAX_REL_ADJUST`（0.2%）にも掛からない
3. 新アンカーは裏拍の上に乗る。以後**格子とコムが一致する**ので、候補ごとのロック
   移動量は ±0.04拍 に収まり、`side_lock_offset` も `branch_indices` も異常なしと答える。
   **片側が丸ごと裏拍だと分裂が起きないので、層6は原理的に検出できない**
   （`branch_indices` の rustdoc が「構造上は排除できない」と書いていた失敗モード）
4. その格子から整数拍を4通り出しても全部が裏拍。**A/B 形式が答えを含んでいなかった**

### 分かったこと

- **層6（側ごとの位相合意）は「少数派が裏拍」しか直せない。** 片側全体が裏拍のときは
  何も言わない。これは実測された制限であって理論上の懸念ではなくなった
- **`|shift|`（ロック移動量）が小さいことは健全さの証拠にならない。** 格子が裏拍に
  乗り切ると移動量はむしろゼロに近づく。診断を読むときに最も間違えやすい点
- **折り畳み（小節位相）の答えは、格子のサブ拍位相が正しいときしか意味を持たない**
  （上の `Kamurogiku` の項）

### 測った結果（2026-08-04）

上に書いてあった「次の一手」の 1 と 2 を実施した。**2 は否定された。**

#### 1. コム曲線（`offbeat_diag`、Kamurogiku）

`near_d`（表拍側の枝）は小節8 の **+0.22 から末尾 +0.00 へ単調に落ちる**。
272小節 = 1088拍で −0.23拍 ＝ **−0.021%**、`intro_bpm` 由来の周期誤差 −0.0257% と一致する。
つまり伝播格子は**アウトロでは真の拍にほぼ正確に乗っている**（`near_d` = −0.01）。
`far_d` は逆に −0.29 → **+0.50** へ動き、小節192 以降は**コムが far 枝を選ぶ**。

**refit は直すものが何も無いところに +0.0254% を入れた**ことになる。上の表で
`outro_bpm` 由来が −0.0011% と当たっているのと同じことを、格子側から見た形。

勝ち幅は薄い。`far/near` は moved 窓で **1.003 / 1.074 / 2.069**（min/median/max）——
**裏拍は 7% しか勝っていない**。いっぽう `lock_beat_phase` が実際に見る
`best/zero` は **1.063 / 4.196 / 15.566** で、`LOCK_CLEAR_WIN_RATIO`=1.05 は
**素通しになる**。ゼロ点が2つのピークの谷に居るせいで、この比は
「裏拍がどれだけ決定的に勝ったか」を何も測っていない（`WindowStats` の rustdoc どおり）。
**閾値を上げても効かない。比べる相手が違う。**

#### 2. 側をまたいだ位相の一致（層7）は使えない

60曲で「イントロ側候補のロック移動量の中央値」と「アウトロ側のそれ」の差を測った
（生データ `testdata/click_phase_survey_60_after.txt`）。分布は
**中央値 0.047 / p90 0.200 / 最大 0.348拍**。Kamurogiku は **0.218 で4位**にすぎず、
上位は良品が占める:

| |Δ| | 曲 | 素性 |
|---|---|---|
| 0.348 | Sakura Photograph | 一様オフセット（既知の良品） |
| 0.243 | Tame Lie One Step | 同 |
| 0.242 | Andai Tak Berpisah | 同 |
| **0.218** | **Kamurogiku** | **裏拍（不良）** |
| 0.214 / 0.200 | Kekka Orai ×2 | 一様オフセット |
| 0.189 | Shirube | 同 |

**Kamurogiku を切り出せる閾値は存在しない。** さらに前提そのものが間違っていた ——
両側の差は 0.218拍であって**半拍ではない**。半拍なのは
「コムが選んだ枝と真の拍の差」（`far_d` +0.50 対 `near_d` −0.01）で、
これは片側の中で閉じており、側をまたいで比べても出てこない。**層7 は棄却。**

#### 3. キック帯は候補になるが、単独では決まらない

`offbeat_diag` の `kick0/kickbest`（低域が delta 0 を支持する度合い）は Kamurogiku の
moved 窓で **22/22 が >1**。ただし60曲へ広げると **moved 窓 730 のうち 614（84.1%）**、
**全 moved 窓で >1 になる曲は 47曲中 21曲だけ**（生データ
`testdata/offbeat_survey_60.txt`、47/60 曲が moved 窓を1つ以上持つ）。
**有力な材料ではあるが、そのまま規則にはできない。**

## 残っている懸念

- `lock_beat_phase` は**拍**にしか吸着せず、小節頭（mod-4）を見ない。アンカーが1拍以上
  ずれた曲では吸着先が小節頭でない拍になり得る。上の小節位相補正が入ったことで
  伝播格子由来のずれは消えたが、この層自体の性質は変わっていない。
  **裏拍（半拍ずれ）は層6が側ごとの合意で潰すが、少数派のときだけ**（上節）。
  `lock_beat_phase` 単体を直接呼ぶ経路（`beat_drift_diag` など診断、およびエンジン側）
  にも効かない
- **ミックス側のアウトロ整合は未確認。** エンジンの `outro_start_out` は fd からの
  伝播ではなく**ファイル終端**から逆算し（`analysis.rs` の「Production ends on a bar」）、
  そこに ±半拍のローカル refine と2仮説の選択が乗る。位相の出所が違うので、
  ここで測ったずれがそのまま効くとは限らない。テールが 0.64〜3.86小節ばらつくため
  この統計では判定できず、実ミックスを書き出して聴く（AGENTS.md「確認手順」）以外にない
