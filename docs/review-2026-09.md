## 3. 統合前レビューで見つかった主な問題

### 3.1 アーキテクチャ評価（統合前・統合後とも概ね維持）

良い点:
- `funkot-core`（解析・ミックス・C ABI）と `funkot-cli`（cpal・キー・WAV）の分離が明確
- Pull 型 2デッキ。ローダーが decode → analyze → stretch をオフラインで済ませ、`render` は事前レンダリング済みバッファの合成
- T0（次曲 intro end）逆算の遷移、HPF バススワップ、fade ペアが一貫
- フェード端点の bit-exact テスト、Android 実機制約、失敗履歴のドキュメント化

### 3.2 P0（統合前）

**nav 遷移が realtime audio callback で位相アラインを実行**  
自動遷移には `set_realtime` ガードがあったが、左右キーの `begin_transition_to` には無く、cpal/FFI コールバック内で重い相関計算が走り得た。

→ **統合後: 解消。** `engine.rs` の `begin_transition_to` に同じガードが入り、worker 未着時は nominal entry。CHANGELOG にも記録あり。

### 3.3 P1（統合前から継続）

| 項目 | 内容 |
|---|---|
| CI | `push` / `PR` で走らない（`schedule` 12h と `tags` のみ） |
| キャッシュ書き込み | `cache::store` が `fs::write` 直書き。tmp+rename なし |
| content_hash | 先頭+末尾 64KiB + 長さのみ。中盤差し替えに弱い |
| ファイル肥大 | `main.rs` / `label_session.rs` / `engine.rs` / `analysis.rs` が 2500〜3300 行 |
| ミックスバス | peak ガード／ソフトクリップなし。f32 仕様だが live ではクリップし得る |
| メモリ | トラック全体を RAM 保持（後述の `docs/memory.md` で整理済み） |
| 依存監査 | `cargo audit` / `cargo deny` なし |

### 3.4 P2

- `cache_path` の hash 検証なし（`../` で cache 外へ書ける余地）
- CLI 本番が `funkot-core` を `features=["testutil"]` で必須依存
- `--highpass-hz` の `alias = "lpf-hz"`（意味が逆で事故のもと）
- 不正 JSON を黙殺（原因がログに残らない）
- FFI の同一 handle 並行呼び出し禁止が未文書化
- Docker の apt パッケージがバージョン未固定

## 6. テスト・検証について

### 強い（このまま維持してよい）

- フェード端点の bit-exact、prev 残留なし

- first-live の provisional outro 回帰
- 実音源での sha256 一致・遷移クリップ聴感・ピーク記録
- Android 実機制約（API 26、16KB ページ、libc++_shared）

### 穴（追加するとよい）

- ミックスバス peak の検証
- サンプルレート多様性（golden はほぼ 44.1k 固定）
- 非 Funkot BPM 範囲外
- キャッシュ非アトミック write / 並行 store
